# 需求记录

## 用户目标

基于 `doc/` 中的提示词文档制作一个本地网页版工具：用户选择步骤、填写相关需求，网页生成可复制的提示词。用户希望后续丢失聊天上下文时，仍可从项目本地的结构化文件继续工作。

## 首轮对齐记录

以下记录用户在会话中的原始选择及最终采用的理解；不把未明确表达的内容伪装成直接引述。

| 项目 | 用户表达 | 最终记录 |
|---|---|---|
| 覆盖范围 | “做2”；随后明确“模板来源：固定用第2套” | 本次实现按 `doc/Duo 三模型精简提示词.md（含 AGENTS.md 规则）.md` 这一套精简提示词实施。若“做2”原意是制作两整套而不是使用第 2 套文档，仍待确认；当前实现范围不因此扩大。 |

## 回写与本地记录的决策来源

- 初始对话中用户表达了“最好还有回写功能”；具体实现语义由后续方案收敛为：用户选择 AGENTS.md，唯一目标章节不存在时追加，存在一次时替换，重复时拒绝写入；写入前预览并确认。
- 用户随后要求把项目结构性文件和上下文整理到本地，并在本轮要求 P3 复核、再要求实施。V1.3 本地记录目录采用 `PRJ_00_AgentPrompt/docs/`，记录文件清单见 `PLAN.md`。

## 非目标

- 不调用在线 AI 服务，不需要 API Token。
- 不做历史记录、通用导出功能或语言切换。
- 不修改 `doc/` 源文件，不自动改写仓库里的 AGENTS.md。
- 不提交、不推送、不合并。

## V1.4 补充需求：提示词文档落盘规范

用户希望生成的提示词明确告诉模型：每个工作流阶段应在目标项目的哪个相对路径下生成、更新或归档什么文档，以便不同阶段的上下文能够保存在项目本地并继续使用。

- 文档根目录默认 `docs`，可编辑并记忆；以目标项目根目录为相对基准。
- 各步骤的文件清单和写入语义以 `handoff/HANDOFF_latest.md` 的 V1.4.1 定稿为准。
- 文件规则区分规范文件（按要求原位更新）与带日期的归档（同名追加 `_2`、`_3`，不覆盖）。
- 只读/Plan 模式无法写入时，在回复末尾输出“待落盘文件”（路径及完整内容），后续由实施模型按最新 Handoff 落盘。
- 文档根目录只允许相对路径；非法或空路径回退 `docs` 并提示。页面保留原输入值，生成时使用规范化结果。

## V1.4.3 补充需求：P1 任务类型回填一致性

用户报告：P1 任务类型未切换时，生成结果中的任务类型与页面默认/显示值不一致；切换任务类型后才一致。

- P1 任务类型控件、已保存状态和生成预览必须始终一致。
- 页面初始化/恢复已保存状态时，不得要求用户先切换任务类型才能纠正预览。
- 保持现有 `Bug` 默认值、`Feature` 选项、localStorage 存储结构和生成模板不变；修复字段回填映射。
- 具体根因和验收条件以 `handoff/HANDOFF_latest.md` V1.4.3 及 AC26 为准。

## V1.4.4 补充需求：P1 任务类型一致性（复报与可验证性）

用户再次报告同一现象：P1 任务类型未切换时，生成结果中的任务类型与页面显示的默认值不同；切换后才一致。需求与 V1.4.3 相同，本次不新增功能范围，只补充：

- 修复必须能被自动自测覆盖：字段回填映射需为可在 `selftest.html` 中调用的纯逻辑，而不只依赖人工检查。
- 已保存的任务类型不是 `Bug`/`Feature`（如空串、旧值）时，控件与预览也必须一致，统一回退 `Bug`。
- 默认值、选项、localStorage schema 和提示词模板仍保持不变。具体以 `handoff/HANDOFF_latest.md` V1.4.4 及 AC26 为准。

## 验收与安全要求

- 提示词输出与指定源文档保持一致，只替换明确规定的字段和角色占位符。
- 未经实际执行的验收项只能标记为 `NOT TESTED`。
- AGENTS.md 回写只作用于用户明确选择的文件和唯一目标章节，回写测试使用临时文件。
- 本地项目记录只记会话中有依据的信息；不确定之处标记“待确认”。
